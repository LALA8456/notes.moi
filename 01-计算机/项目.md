1. **为什么要有 Controller、Service、Repository 这三层？**
    
    - 去点开 `UserController`，看它里面有没有 `@GetMapping`。你会发现它只负责“接收前端请求，然后调用 Service”。
        
    - 去点开 `UserService`，看里面有没有 `@Transactional` 或者密码加密的逻辑。你会发现它负责“真正的业务规则”。
        
    - 去点开 `UserRepository`，看它有没有 `@Query`。你会发现它只负责“和数据库说话”。
        
    - **思考**：如果我把这三层写在一个文件里会怎样？（结论：代码会变成几千行的“屎山”，改一处报错三处）。这就是设计的意义。
        
2. **为什么前端要分 API 层和 Vue 页面？**
    
    - 去 VS Code 看 `src/api/user.js`，里面是不是只有 `axios.get` 和 `axios.post`？这叫“接口层”。
        
    - 去 `src/views/system/user/index.vue`，里面是不是全是 `<el-table>` 和 `<el-button>` ？这叫“视图层”。
        
    - **思考**：如果把调接口的代码直接写在 Vue 文件里，项目大了以后，前端改个接口地址要改几百个文件。这就是分层的意义。
        

#### 第二步：用“外科手术思维”去修改生成的功能（避免纯搬运）

1. 用代码生成器生成一个“待办事项（Todo）”模块。
    
2. 运行它，看着页面发呆。这时候你可以做标准的增删改查，体验一下“搬运”的便利。

    - **规则**：当待办事项状态变成“已完成”时，必须自动记录完成时间，并且不允许再次修改。
        
    - **你怎么写？** 打开生成的 `TodoServiceImpl.java`，在里面加一个 `if` 判断。如果在 Controller 层判断行不行？（不行，因为 Controller 只管接客，不碰业务）。
        
    - **规则**：待办事项的标题不能重复。
        
    - **你怎么写？** 在 Service 层调用 Repository 去数据库查一下是否已存在。
        
4. **遭遇报错与修复**：这个“自己加规则 -> 报错 -> 查资料 -> 修复”的过程，就是你真正把“搬运”变成“拥有”的过程。

### AI 应用开发项目（RAG、MCP、智能体架构）

**🎯 核心能力：把大模型接入到真实业务中，解决具体问题。**  
很多人以为调个 ChatGPT API 就是 AI 开发了，那是大错特错。企业要的是“知识库问答”、“自动填表”、“智能客服”。

**在 ELADMIN 里怎么练？**  
等你把 ELADMIN 的“待办事项”跑通后，可以给它加一个**“AI 智能助手”**模块：

- **RAG（检索增强生成）练手**：把你项目的后台操作手册（比如怎么写 SQL、怎么配置菜单）扔进一个简单的向量数据库。在后台加个搜索框，用户问“怎么新建用户？”，后台去向量库找相关文档，组装成 Prompt 发给大模型，返回答案。**核心是搞懂：文本切分、向量化、召回、Prompt 组装。**
    
- **智能体（Agent）练手**：给待办事项加个“语音输入”按钮。前端录音 -> 后端调用语音转文字 API -> 调用大模型提取“任务标题”和“截止日期” -> 自动填进表单。**核心是搞懂：工具调用（Function Calling）、流程编排（LangChain）。**

### 2. AI 编程项目（Vibe Coding 快速交付）

**🎯 核心能力：利用 AI 快速出原型，把想法变成可跑的软件。**  
“Vibe Coding”的意思就是：你负责出想法和架构，AI 负责写具体的重复代码，像开着“自动驾驶”一样写代码。

**在 ELADMIN 里怎么练？**

- **用 AI 帮你看懂代码**：不要再一行行啃代码了。选中一段看不懂的 Service 层代码，直接问 Cursor、通义灵码或 DeepSeek：“帮我解释这段代码的业务逻辑，并画出时序图”。
    
- **用 AI 生成 CRUD**：不要再手写增删改查了。描述你的需求：“帮我写一个 `TodoController`，包含分页查询和状态更新接口”，让 AI 生成代码，你负责检查和修改。
    
- **用 AI 做前端 UI**：描述你要的页面：“用 Vue3 + Element Plus 写一个卡片列表，展示待办事项，带状态切换开关”，AI 会直接输出可用的 Vue 代码。你的精力应该放在**拆解需求、设计数据库、定义 API 接口**上。

### 3. 技术轮子类项目（底层原理理解）

**🎯 核心能力：造轮子，深挖底层，面试时展现硬实力。**  
PPT 里明确说了：“面试官喜欢考察底层原理的理解”。只会调 API 的人一抓一大把，知道 MySQL 索引怎么优化、Spring 事务为什么会失效的人，才是企业真正想要的。

**在 ELADMIN 里怎么练？**

- **手写简易版 IoC/AOP**：你天天用 `@Autowired` 和 `@Transactional`。去花一周时间，自己用 Java 反射和动态代理，写一个只有 200 行的迷你框架，实现自动注入和事务拦截。写完你就彻底懂 Spring 了。
    
- **手写简易版 MyBatis**：ELADMIN 用的 JPA，你可以自己用 JDBC 写一个极简的 ORM 框架，只需几行注解就能把 SQL 查出来的数据映射成 Java 对象。搞懂什么是“反射、动态代理、JDBC 连接池”。
    
- **深挖 Redis 缓存**：看 ELADMIN 里 Redis 是怎么用的。研究“缓存穿透、缓存击穿、缓存雪崩”怎么解决。用 Redis 的 `setnx` 手写一个分布式锁。
    
- **阅读源码**：不要只写业务，去读 Spring Boot 的 `run()` 方法，看它是怎么一步步启动 Tomcat 的。去读 `DispatcherServlet`，看一个请求是怎么分发的。
